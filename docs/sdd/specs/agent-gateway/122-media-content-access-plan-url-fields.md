# SPEC-122: Media Content Access Plan URL Fields

## Status

Accepted for the current iteration.

## Context

The shared `MediaAssetContentAccessPlan` contract fixture already includes
`runtime_path`, `dashboard_path`, and `content_url`, but Go's runtime response
currently exposes only the runtime content endpoint. That leaves frontend and
dashboard callers to reconstruct deterministic URLs outside the Go-owned media
asset boundary.

## Boundary Analysis

Go owns:

- deterministic media asset runtime route construction;
- stable dashboard proxy URL hints that point to Go-owned content policy;
- access plan shape and side-effect declaration.

Python owns:

- dashboard presentation and proxying;
- OCR/VLM/file parsing/RAG/AI interpretation of media content.

Out of scope:

- content streaming behavior changes;
- remote media downloading;
- OCR/VLM/RAG/AI execution;
- dashboard UI redesign.

## Decision

Extend `MediaAssetContentAccessPlanView` with:

- `runtime_path`: the Go access-plan endpoint for the asset;
- `dashboard_path`: the dashboard access-plan proxy path;
- `content_url`: the dashboard media content proxy path.

The fields are generated by Go from `asset_id` and remain read-only. Python can
consume or display them but should not own the policy.

## Acceptance

- Go access-plan responses include the three URL fields.
- Existing contract fixture expectations remain aligned.
- Target Go tests and Python dashboard/contract tests pass.
- TODO is cleared at the end of the iteration.
